# SEC Filings

API + UI on top of the SEC's EDGAR data. pnpm monorepo:

```
backend/    Express 5 + TypeScript (strict) + zod + es-toolkit
frontend/   React 19 + Vite + TanStack Router (file-based) + TanStack Query + MUI + Tailwind v4
```

## Getting started

Requires Node 22+ and pnpm 10.

```bash
pnpm install
cp backend/.env.example backend/.env   # set SEC_USER_AGENT
pnpm dev                                # backend :3000, frontend :5173
```

| Script                            | What it does                                    |
| --------------------------------- | ----------------------------------------------- |
| `pnpm dev`                        | Run backend and frontend in watch mode          |
| `pnpm typecheck`                  | `tsc --noEmit` in both packages                 |
| `pnpm lint` / `pnpm lint:fix`     | ESLint (typescript-eslint strict, type-checked) |
| `pnpm format`                     | Prettier                                        |
| `pnpm --filter @sec/backend test` | Vitest unit tests                               |

The frontend calls `/api/*`, which Vite proxies to the backend (prefix stripped).

## Architecture

### Backend — `backend/src`

```
index.ts              entrypoint: reads env, builds app, listens
app.ts                composition root: repository → service → controller, middleware
config/env.ts         zod-validated env vars (fails fast on boot)
middleware/           404 + error handler (ZodError → 400, HttpError → status)
lib/http-error.ts     HttpError / NotFoundError / UpstreamError
domains/filings/
  filing.domain.ts    Filing — the standardized domain type (zod schema + inferred type)
  edgar.schemas.ts    zod schemas for raw EDGAR responses
  filings.repository.ts  EDGAR HTTP access (User-Agent, ticker→CIK map cache, validation)
  filings.service.ts  business logic: columnar → Filing[], sorting
  filings.controller.ts  HTTP: validate params, call service, shape response
  filings.routes.ts   Express router
```

Layers depend only downward via interfaces (`FilingsRepository`), so the service can be tested
with a fake repository and `createApp()` can be given one in integration tests.

### Frontend — `frontend/src`

```
main.tsx                         providers: MUI theme, QueryClient, Router
routes/                          file-based routes (routeTree.gen.ts is generated by the Vite plugin)
  __root.tsx                     layout + devtools
  index.tsx                      ticker search
  companies.$ticker.tsx          filings table
lib/api-client.ts                fetch wrapper (base URL, JSON, ApiError)
services/filings/
  filings.domain.ts              Filing type (mirrors backend)
  filings.service.ts             plain fetch functions
  filings.hooks.ts               query keys, queryOptions, useFilings()
```

MUI and Tailwind coexist via CSS cascade layers (`theme, base, mui, components, utilities`):
MUI styles go in the `mui` layer, so Tailwind utilities win when both apply. The layer order is
emitted through Emotion `GlobalStyles` in `main.tsx`; it must come before any MUI style.

## EDGAR API notes

Docs: <https://www.sec.gov/search-filings/edgar-application-programming-interfaces>,
<https://www.sec.gov/os/accessing-edgar-data>

**Access rules**

- No auth/API key. **Must** send a descriptive `User-Agent` with contact info, or you get 403.
- Fair-access limit: **10 requests/second** per IP. Exceeding it gets you temporarily blocked.

**Endpoints relevant to this project**

| URL                                                                           | Contents                                                                                        |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `www.sec.gov/files/company_tickers.json`                                      | ~10k `{cik_str, ticker, title}` rows (~800 KB). One CIK can have many tickers (JPM, JPM-PC, …). |
| `data.sec.gov/submissions/CIK{10-digit}.json`                                 | Company metadata + filing history in **columnar** form                                          |
| `data.sec.gov/submissions/CIK…-submissions-001.json`                          | Older filings, listed in `filings.files`                                                        |
| `www.sec.gov/Archives/edgar/data/{cik}/{accessionNoDashes}/{primaryDocument}` | The actual document (CIK **without** leading zeros)                                             |
| `…/{accessionNoDashes}/{accession-with-dashes}-index.htm`                     | Filing index page                                                                               |

Other APIs we're not using yet: `api/xbrl/companyfacts`, `companyconcept`, and `frames` for
structured XBRL financials (revenue, EPS, …). These are good candidates for an extension.

**Submissions response gotchas**

- `filings.recent` holds at least the last year or the last 1,000 filings, whichever is more.
  JPM has **~26k** "recent" filings (mostly 424B2 prospectuses), so pagination must happen
  server-side.
- Older filings live in separate files (`filings.files[]`), which take extra requests to load.
- Missing values are `""`, not `null`.
- Foreign private issuers file **20-F / 6-K** instead of 10-K / 10-Q. **Spotify has no 10-K**,
  so the summary's "latest 10-K" must handle that (null, or fall back to 20-F/40-F).
- Amendments use separate form types (`10-K/A`). Decide whether filters include them.
